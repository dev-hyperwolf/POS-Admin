canvas / canvas2 exist for one job — the page-level backdrop behind kanban lanes and dense tables. In Pipeline they'd also become the default icon-plate, table-head, hover and notes-panel fill, in 15 files.
High
background: P.canvas2 → batch icon plates, evidence tiles, stat boxes, meter tracks  ·  background: P.canvas → table heads, filter bars, notes panels, hover states, sticky footers  ·  62 call sites, 15 files

2
The active nav item and its own sidebar were the same colour
Pipeline's module sidebar (Batches / Inventory / Products…) painted its active row the exact background the sidebar already sits on. Every other app's equivalent sidebar uses a lighter fill for the active row than its own backdrop — Pipeline's didn't, so "Batches" never visibly looked selected.
High
Engage: sidebar background P.bg  →  active row P.surface2 (visibly deeper)
Pipeline: sidebar background P.canvas  →  active row P.canvas (identical — zero contrast)

Fix applied. Active row is now surface (white) with a small raised shadow, popping forward off the cool sidebar the way a selected tab should — plus the existing yellow left-accent bar. Hover moved to surface3 so it reads as a distinct, lighter step than the active state.

3
Round 1's own rule — selection is ink, not accent — hadn't reached the Inbox
The Invoice Inbox's view toggle ("Needs you" / "All") and its status filter chips (All / Auto-Posted / Mapped…) both filled the active option solid yellow. That's the exact pattern round 1 finding 1 fixed on the POS register — it just hadn't propagated to this screen.
Med
ViewToggle active → background: P.accent, color: P.accentInk
StatusChips active → background: P.accent, color: P.accentInk
Same screen also has zero other accent use — so this WAS the screen's "one accent," just applied to the wrong thing (a filter, not an action).

Fix applied. Both now fill ink on the active option (white text on black), matching how every other tab/filter group in the product marks "this is selected." Yellow stays reserved for the one primary action per view.

4
Two table components still exist
Round 1 flagged "three of everything" as the real cohesion gap; phase 4 merged Pill and EmptyState behind aliases, but DataTable (pos/atoms.jsx) and HDTable (shared/hd-ui.jsx) are still two separate implementations with different defaults.
Med
TraitDataTable (POS)HDTable (Hyperdrive)
Row height40px default, 32px dense34px fixed
Empty statePlain "No results" text rowCaller supplies its own (usually EmptyState now)
SelectionBuilt-in selectedKeysNone — callers hand-roll it per screen
Sticky headProp-drivenCaller sets position:sticky manually

Risk. Every Hyperdrive table (Pipeline, Engage) hand-rolls row height, sort icons and empty/selection behaviour per screen, because there's no shared component to inherit it from. That's exactly how the Inbox screen above ended up with its own one-off selection colour — the fix in this audit doesn't prevent the next one.

Fix. Same move as Pill/EmptyState: make HDTable a thin wrapper over DataTable that maps Hyperdrive's plain <thead>/<tbody> call sites onto the shared column/row API, so density, selection and empty-state come from one place going forward.

5
A handful of buttons fight their own variant with an inline override
A few call sites pick variant="accent" and then inline-override the colour to something else — usually red for a destructive action. The variant system already has the right name for that.
Low
logistics/lorder.jsx:267 — <PBtn variant="accent" icon="user-off" style={{ background: P.bad, color: '#fff' }}>Cancel order</PBtn>

Fix. Use variant="danger" — it already renders exactly this, from the token, with no inline style needed. Cosmetically invisible today; the risk is the inline override silently stops matching if danger's styling ever changes.
