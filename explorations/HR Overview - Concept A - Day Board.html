Track 3 · M1 read-only · reads GET /api/hr/employees, /compliance/expiring, /incidents, /calloffs
The idea

Overview answers "what needs a look today," ordered by urgency — not a directory.

Everything on this screen is a card ranked by how soon it needs a human, not a table you scan top-to-bottom. The four numbers up top are a thin summary strip, not the point of the page. Clicking any card opens the same drill-down side panel — the list never grows past what fits without scrolling, because low-urgency items simply don't get a card.

Every name and number below comes from qa/fixtures/hr/*.json — the same fixtures qa/hr_airtable_stub.py serves in tests. Nothing here is invented. M1 is read-only: every action button in the "needs a person" lane is disabled and tagged M4 because approve/reveal/escalate are write actions that ship later.

HR scope: hr:read
What hr:read sees
  • Visible — names, roles, entity/store, document status flags, incident & call-off summaries, aggregate counts.
  • Never returned — SSN, driver's license, passport, home address, emergency contact. These never leave the server for any role on this route (excluded by construction in airtable_read.py's field allowlist, not filtered after the fact).
  • Hidden here — email/phone (internal-class). Detail view only, not this screen.

Needs a person

— items awaiting a manager decision. M1 renders these disabled; the actions ship in M4.
