# Canonical data model — written down as it actually is (2026-09-09)

This is not the model we want. It is the model the twelve repos implement today, reconciled across
copies so that Phase 3's contract package has one place to start from. Field-level detail per repo
is in `repos/<repo>.datamodel.md`; this file records, per concept, the fields that exist in every
copy, the fields that disagree, and the conventions (id, money, time, status, tenant) each copy
uses. "All brand backends" = hemp-backend, stilo-backend, hyperwolf-backend.

## 0. Conventions as found

| Convention | What the code does | Where |
|---|---|---|
| Primary id | Mongo `_id` ObjectId **plus** an application string id (`memberId`, `productId`, `orderId`, `storeId`, `regionId`) generated by `Math.random()` (hemp `common/utils.js:222-228`) or copied from Blaze; joins are done on the string id in application code | all brand backends; refs used in 2–4 places per repo, one of them dangling (`ref:"Author"` vs model `Authors`) |
| Money | `Number`, **dollars**, 2-dp rounding in JS (`roundToTwo`, `toFixed(2)` → sometimes a **String** into a `Number` field). No `Decimal128`, no cents. Most order money is inside untyped `Object` fields (`cartData`, `everFlow`, `promotionData`) | every backend; `Discrepancy.discrepancyAmount` is a `String` |
| Time | `createdDate`/`updatedDate` epoch-ms `Number` set by controllers (majority); `Date` in hyperdrive/distribution conn3/promotion-backend; formatted `String` in log models; `timestamps:true` on 3 models estate-wide | see `ARCHITECTURE-MAP.md` §4.6 |
| Status / enum | free `String` at the schema, sometimes a Joi enum at the route; `status` is `Boolean` on some models and `String` with `default:false` on others (hemp/stilo `Brand`, `Category`) | all |
| Tenant key | `retailerId` (hemp) / `storeId` (stilo) / `platform` enum `hyperwolf\|stilo\|hemp` (distribution, promotion) / which DB connection (hyperwolf, promotion-engine) / `fleetId` (hyperdrive). Client-supplied, unindexed, not derived from the caller | all |
| Soft delete | absent on ~95% of models; five conventions where present | see map §4.7 |
| Indexes | hemp: 6 explicit across 56 models, `Order` 0; stilo: 3 of 56; hyperdrive: 3 dead (field path does not exist); distribution: `KitDistributed` 0; promotion-backend `HempProducts` 0 | `repos/*.md` §5 |

## 1. Person

### 1.1 Customer (`Member`) — hemp-backend, stilo-backend (`Member`); hyperwolf-backend (`BlazeUser`)

Common fields (hemp/stilo): `memberId` (String, random), `email`, `phone` (unique), `password`
(bcrypt, cost 10–12 inconsistently), `firstName`, `lastName`, `dob` (Number), `licenseNumber`,
`idImage` (S3 URL, **public-read**), `memberType`, `memberShipGroup` (default "Delivery"),
`deliveryAddress` (Object), `klaviyoProfileId`, `status` (Boolean), `isVerified` (Boolean, **set from
request body** in hemp), `verifyMethod`, `ageCheckerUid`, `diditSessionId`, `walletAmount` (Number
dollars, **settable by request**), `averageSpent`, `retailerId`/`storeId`, `memberNotes`,
`hotNotes[]`, `blockOnlinePayments{}`, `createdDate`.
Hyperwolf's customer is `BlazeUser { email, userData: Object (Blaze member), fhlOtp, personaUid,
sessionToken, inquiryId }` — a different shape keyed by Blaze.
Our estate: `hw_identities` (int autoincrement, phone/name/dob fingerprints, gov-id hash),
`idv_people` (`p_`+uuid hex, `vendor_data` unique, `blaze_member_id`, `hw_identity_id`).

### 1.2 Staff (`Admin`) — five copies, at least two physical collections (HEMP-DB shared by hemp, stilo, distribution; HW-DB; hyperdrive's own)

`{ firstName, lastName, name, email, password, phone, status, userRoles: Array<String>,
stores: Array, isSuperAdmin: Boolean, deviceToken[], createdDate: Number, lastLogin: Number }`
(hemp/stilo/distribution) vs `{ name, email, password, createdDate, lastLogin, isSuperAdmin }`
(hyperdrive) vs hyperwolf `Admin` (6 fields, **plaintext password**). `generateAuthToken()` on the
model signs `{_id, email, isSuperAdmin}` HS256 with `JWT_ADMIN_PRIVATE_KEY`, `expiresIn:"2d"`.
No index on `email` in any copy.

### 1.3 Tenant logins — hemp `Retailer`/`RetailerUser`/`Store`/`StoreUser`, stilo `Store`/`StoreUser`

`Store { storeId (unique), storeName, firstName, lastName, email, phone, password, PIN,
platform, roleId, roleName, isViewUser, subscription, valiDateFrom/To, kml, deviceToken[],
createdDate }`. Same JWT secret as Admin. hemp has both hierarchies; the retailer login route is
never mounted.

### 1.4 Driver (`Fleets`) — hyperdrive (canonical), hyperwolf and distribution (copies)

`{ fleetName, fleetEmail (unique), fleetPhone (unique), fleetPassword, fleetImage (hardcoded S3
default), fleetTransportationTypeId → TransportationTypes, fleetVehicleDetails{}, regionData
{regionId: String, regionName}, terminalData{terminalId, terminalName}, locationData{lat,lng},
lastLocationData, policyFile, idFile, fleetVerificationStatus: pending|verified, fleetStatus:
active|inactive, fleetOnDutyStatus, isDeleted, deletedBy, fleetDisplayId (mongoose-sequence from
1000), createdDate: Date }`. Compound index references top-level `regionId`, which does not exist.
Our estate's `associates { associate_id (slug), store_id, role (free text), email, class }` is the
Bounty/Verify view of the same people.

### 1.5 Roles

`Admin.userRoles[]` free strings → matched by name to `RoleAndPermissions { role: {roleName},
permissions[] }` (hemp/stilo) → merged into the login response → **never checked server-side**;
`staticDB/roles.json` + `user-rules.json` are a second source. `isSuperAdmin` boolean is the only
enforced role, on 4 hemp routes and 0 stilo routes. Frontends: `hwPermissions/hempPermissions/
stiloPermissions/hyperdrivePermissions` arrays in `localStorage`. Our estate: `MANAGER_ROLES =
{"Floor Manager","Admin"}` (Bounty), substring test on role text (Verify).

## 2. Catalog

Indexes on dotted `productData.*` paths |

### 2.2 Taxonomy

`Brand { brandId, brandName, brandSlug, status, image, metaTitle, metaDescription, description,
isBestBrand, isPopularBrand, brandSlugArray[] }`; `Category { categoryId, categoryName (unique),
categorySlug, categoryMenuName, categoryImage, status, faq[], metaTitle, … }`; `WebCategory` (a
second category tree); `MainBrand`/`MainCannabinoid`/`MainStrain` (same SEO-page shape ×3);
`Strain`, `Cannabinoid`, `Terpenoids`, `MainProductTraits`/`SubProductTraits` (trait tree,
`platformAvailability{hyperwolf,hemp,stilo,all}`). Copied per brand backend and again into
promotion-backend per platform. Our estate: `shared/brands.js` (`HW_BRANDS`) and `taxonomy.py`.

### 2.3 Region / store geography

hyperwolf `Region { regionId, regionName, status, openingHours, closingHours (Number), kml }`
(Blaze-synced every 18 min); distribution `Regions { region, platform, status }` +
`SubRegions { kmls[], blazeRegionId, blazeRegionName (compound unique) }`; hyperdrive `Region`
(36 fields, foreign, unused). `ShopTime` and `TimeSlot` (hyperwolf) are two copies of a weekly
hours schedule. Our estate: `store_id` slug, `STORE_TZ` map, `cities.py`.

## 3. Commerce

### 3.1 Cart — `ActiveCart` (hemp/stilo/hyperwolf)

`{ memberId, sessionId, email, cartData: Object (lines), deliveryAddress{}, memberData{},
paymentOption, shippingType, shippingCharges (declared twice), walletAmount, walletPointsUsed,
taxResult{}, subTotal, total, totalDiscount, afterTaxDiscount, promotionData[], availablePromos[],
currentPromos[], invalidCodes[], promoMessages[], upsell{}, reminderSent, holdReset, createdDate }`.
Unique partial indexes on `memberId` and `sessionId`. Totals arrive from the client and are
persisted as sent. promotion-engine reads this collection natively by `memberId|cuid|sessionId`.

### 3.2 Order — five schemas, at least three physical collections

Common core: `orderId` (String), `memberId`/`cuid`/`email`, `status` (free string; Joi
`pending|completed|cancelled` at some edges), `paymentOption`, `deliveryAddress{}` / `userData{}`,
`items[]` / `cartData{}`, `promotionData{}`/`promoCode{}`, `subTotal`, `total`, `afterTaxDiscount`,
`walletAmount`, `walletPointsUsed`, `shippingType`, `shippingCharges`, `trackingId`,
`shipStationOrderId`, `creditTransactionId`, `alpineIQPoints`, `klaviyoProfileId`, `emailStatus`,
`reviewStatus`, `returnRequestStatus`/`approvedItems[]`/`returnItems[]` (hemp), `cashReceived`/
`balanceLeft`/`splitCardAmount` (POS), `fleetId → Fleets`, `onFleetTaskId`, `taskAssignmentMode`,
`driverDetails{}`, `serviceTime`, `expectedArrivalTime`, `orderCancellationReason{}`, CanPay fields
(distribution), `everFlow{}`/`metadata{}` (hyperwolf), `createdDate`/`updatedDate` (Number).
Indexes: hyperwolf/distribution `{cuid}`, `{orderId}` non-unique; hemp none. Our estate: `orders`
(Weedmaps id PK), `pos_sales` (caller id PK, integer cents, `txn_type sale|refund|void`),
`inc_txns`/`inc_lines` (natural composite keys, cents, ex-tax basis).

### 3.3 Payment

No payment model; transactions live on `Order` fields and in vendor systems (CanPay, Stronghold,
LedgerGreen, NMI/LeisurePay/Maverick, Alt36). `PaymentSetting` (stilo) stores processor
client/secret ids as plain fields. `LedgerGreen` (hyperwolf) stores transaction lookups with a
formatted-string date. Card data transits hemp-backend and is logged to Sentry on error.

### 3.4 Promotion

promotion-backend `Promotion { name (unique), code[], description, publishDate, expiryDate,
usageLimit, usageLimitPerUser, status: active|inactive, autoApply, stackable, showingPromoCode,
timezone (default America/Los_Angeles), platform, rule: Mixed, actions: Mixed, rules: Mixed,
ruleTree: Mixed, promoUsage, createdAt }` + `Rule { rule_type: cart|user|product|bogo, … }` +
`Rules` (if/then, unconstrained type) + `Action { type: flat|percentage|product }` + `PromoCode`
(only model with `timestamps`) + `ProductPromoTag` (derived index, unique `{platform, productId}`)
+ `promotionusages` (native, keyed platform+promotionId+member/session).
Brand backends' legacy `Promotion` (40 fields: `promotionType`, `discountType`, `criteriaGroups[]`,
`promoCodes[]`, weekday booleans, `startDate/endDate` as `Date`, `startTime/endTime` as String)
plus `CartRules`/`ProductRules` (hemp/stilo, byte-identical controllers). Our estate:
`internal_promos`, `wm_promos`, `promo_links.relation ∈ mirrors|supersedes|conflict`, and the
Promotions Suite screens.

### 3.5 Wallet / points

`Member.walletAmount` (Number $), `MemberWalletReasons`, `walletLogs` (two divergent copies in
hemp), `Order.alpineIQPoints`, AlpineIQ API. No ledger. Our Bounty: `inc_points { contest_id,
round_key, associate_id, kind: earned|adjusted|recorded_paid, cents }` with a UNIQUE constraint —
the only append-only points ledger in the estate.

## 7. What the contract package must therefore define (input to Phase 3)

1. **Ids**: `ObjectId` string (24-hex) as the transport form for every production entity;
   external ids (Blaze, Meadow, Treez, Weedmaps, Didit) as `{source, id}` pairs; our slugs
   (`store_id`, `associate_id`) as display keys, never foreign keys.
2. **Money**: integer cents on the wire and in new storage; a single `dollars→cents` boundary when
   reading legacy `Number` fields; `money_basis` (`ex_tax_net` | `inc_tax`) stated on every total.
3. **Time**: ISO-8601 UTC strings on the wire; epoch-ms legacy fields converted once at the adapter.
4. **Enums**: `OrderStatus`, `TaskStatus`, `FleetStatus`, `MemberType`, `Platform`
   (`hyperwolf|hemp|stilo`), `Role` (one vocabulary replacing `userRoles[]`, `isSuperAdmin`,
   `MANAGER_ROLES`, `viewer|analyst|admin`), `PromotionStatus`, `RuleType` (six, from
   promotion-engine), `TxnType` (`sale|refund|void`), `VerificationStatus` (Verify's ten).
5. **Entities**: Person (customer/staff/driver as one shape with kind), Store, Region, Product
   (one shape with `source: blaze|first-party`), Cart, Order, OrderLine, Promotion, Task, Fleet,
   Points ledger entry, Verification session.
6. **Errors**: `{ error: { code, message, details? } }` with real 401/403/404/409/422/500 — none of
   the production backends return 401/403 outside two middlewares today.
7. **Events**: `order.created`, `order.completed`, `task.status_changed`, `verification.decided`,
   `points.earned`, `promotion.consumed` — HMAC-signed the way Verify already signs.
